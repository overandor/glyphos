The Problem

Kyle would fake his homework.

Kyle says he did the work on a different computer. But did he? The school grading system accepts a blank paper with a name on it and gives it a C-minus. Most verification systems are that school. HDAR is not that school. HDAR reads the essay, recomputes the answer, and checks the fingerprint on the paper.

01 / SEAL

Host A seals the workspace

Machine A commits every file to SHA-256 content blocks, builds a manifest, signs it with Ed25519. The private key never leaves Host A. The signature is the mother saying "yes, that's really Eric's homework."

✓ Ed25519 signature
02 / TRANSPORT

Capsule enters the wild

The sealed capsule — manifest, content hashes, signature, lineage pointer — travels to Host B. No source code exposed. No private key transmitted. The capsule is a sealed envelope with a fingerprint on the seal.

✓ Content-addressed capsule
03 / EXECUTE

Host B does the work

Host B opens the capsule, proves it has the right image, retrieves state, receives a temporary lease, advances the computation, and produces a successor commitment. Every step is receipted.

✓ Bounded execution + receipts
04 / VERIFY

Independent verifier checks

A Rust verifier independently recomputes the pipeline output hash from actual workspace files — not from the report field. Asking Butters to verify Butters is pointless. The verifier is Token, not Butters.

✓ Multi-implementation verification
05 / INJECT

Failure injection catches cheats

Ten attack vectors tested: manifest corruption, E2 capsule swap, fabricated platform strings, hash collision attempts, signature forgery, lineage breaks, replay attacks, capsule tampering, missing blocks, fake reports. All ten caught.

✓ 10/10 attacks detected
06 / REPRODUCE

Reproduction matrix proves determinism

Five different machines from five different environments solve the same problem. If they all get the same answer, the computation is deterministic — not lucky. The release bundle freezes the exam questions so nobody can change the problem after the fact.

✓ Cross-platform determinism

Strategic Position

The barrier to entry is you need to be a giant nerd.

Nobody else is doing host-detached archival runtime proof with content-addressed capsules, cross-platform deterministic pipeline verification, and epistemic overlays. The barrier to entry is not money — it's understanding Ed25519, SHA-256 content addressing, Merkle trees, capsule formats, lineage chains, attestation systems, multiple provider integrations, Rust, Python, GitHub Actions, E2B sandboxes, and failure injection testing. That filters out 99% of people who would try to copy this. The remaining 1% would rather build their own version than copy yours. The moat is the complexity and the specificity of the protocol design.
